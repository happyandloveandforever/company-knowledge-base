# 新思路怎么进库

你随时会想到新东西。这份文件保证每次加进来的东西，三个月后还有人看得懂、还知道哪张算数。

规则卡：`PAT-RULE-008`。入口卡：`PAT-INDEX-001`。

---

## 你只需要做两件事

**一、把想法说成"技术问题"，不是"效果"。**

| 不行 | 行 |
|---|---|
| 让人更放松 | 高盐液里羟基自由基活不到扩散开 |
| 我们的消杀特别有效 | 液相 AOP 够不着舱壁上的生物膜 |
| 蛋形舱更好看更舒服 | 内表面要同时排净、辐照均匀、避开驻波节点，这三件互相打架 |
| 音疗能助眠 | （这条整个不能写，见 `PAT-IDEA-059`） |

**说不出技术问题的想法，先别进库。** 说得出，就交给我，剩下的我按下面六步办。

**二、任何对外展示之前问一句能不能公开。**

我们自己一旦公开卖、公开展、官网写明原理，就成了我们自己后续申请的现有技术。中国的宽限期不含商业销售。见 `PAT-RULE-006`。

## 六步流水线（我执行，你可以核对）

**第一步 · 写技术问题。** 现有技术为什么解决不了，越具体越好。

**第二步 · 查先案。** 至少三类：同领域专利、竞品的公开销售与官网原理、相关学术公开。

**先写先案卡，再写方案卡。** 顺序反了就会写出自我感觉良好的方案——前面几轮吃过亏：AOP、光触媒、舱内换能器、40Hz、抗结晶涂层，都是先想好了才发现别人早就在卖。

**第三步 · 过闸门。** 四道，缺一不可：

| 闸门 | 问什么 |
|---|---|
| `PAT-RULE-003` 去环境测试 | 拿掉高盐、拿掉中性浮力，问题还在吗？还在＝高盐不是必要条件，降级或打掉 |
| `PAT-RULE-004` 第 25 条 | 有没有写成治疗？带"疗"字的一律重写 |
| `PAT-RULE-005` 组合发明 | 是彼此支持，还是几个模块并排装上？ |
| `PAT-NO3-001` 四条件 | 技术问题独立、技术特征独立、技术效果独立、原型与数据成熟 |

**过不了的，写成"已打掉"卡，写清打掉原因。**

打掉的结论和能写的结论一样值钱——下次不用重查，也不会有人再提一遍。库里现在有 18 张打掉卡，每一张都省下了一次重复调研。

**第四步 · 定状态。**

| 状态 | 含义 |
|---|---|
| 现行 | 当前算数 |
| 待重估 | 没被打掉，但没人推进，重新立项前先复评 |
| 已打掉 | 明确否定，不要再投入 |
| 已取代 | 有更新的结论，卡上写明指向哪一张 |

**新卡取代旧卡时，必须同时把旧卡改成"已取代"。只加不改，库就烂了。**

**第五步 · 归组。** 按 `PAT-RULE-007` 的"特定技术特征"判断：

| 组 | 贡献点 | 独权候选 |
|---|---|---|
| 组一 · 液路与化学 | 高盐液状态量作为准入与流路切换依据 | `PAT-ROAD-A` |
| 组二 · 残余量闭环 | 以实测残余量为反馈的联合优化与准入联锁 | `PAT-IDEA-046` |
| 组三 · 高盐声耦合 | 高盐液作声耦合介质的阻抗与腔体模态 | `PAT-IDEA-049` |
| 组四 · 测量可信度 | — | `PAT-ROAD-B` |
| 组五 · 舱体与表面 | 内表面在五个冲突约束间的联合设计 | `PAT-IDEA-055` |

判断不了就填"未归组"并说明原因。**不要为了整齐硬塞。**

确实出现新的贡献点类别时可以新设组——组五就是这么来的（舱体几何跟前四组的贡献点都不同）。但必须写明它和既有组差在哪。

**第六步 · 写卡跑测试。**

```bash
cp scripts/_template-new-batch.mjs scripts/apply-patent-你的主题.mjs
# 改 BATCH 和 cards 两处
node scripts/apply-patent-你的主题.mjs
node scripts/test-patent-library.mjs
```

校验不通过**不会写盘**，库不会被污染。规则集中在 `scripts/lib/patent-store.mjs`，入库和测试共用同一套，不会两边走偏。

这套校验已经真的抓到过错：五张先案卡漏填标签、七张早期卡缺免责声明，都是它在写盘前拦下来的。

## 改了网页之后必做一步

卡片正文是每次请求现读 `data/*.json` 的，永远新鲜；但页面框架是编译产物。
所以**用搜索卡片内容的办法验证界面，验不出来**——内容是新的，界面可能还是旧的。

改完 `src/` 里的东西，跑：

```bash
npm run build
kill $(pgrep -f next-server | head -1)   # 守护进程会用新产物拉起
sleep 20
node scripts/check-served-ui.mjs         # 只检查编译产物里才有的标记
```

最后一条退出码非 0 就说明服务还在跑旧产物。这个脚本是因为真踩过坑才写的：
`pgrep -x next-server` 匹配不到进程名，kill 空转，界面旧了一小时没人发现。
