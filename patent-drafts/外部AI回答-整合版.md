## 第二部分：三个新角度（第一轮发散，跳出人体信号轴）

### 新角度 A：液路电学指纹诊断（EIS 用于漂浮液系统健康）

```
1. 技术问题：常规水处理系统只监测浊度、pH、余氯等单点化学量，无法感知过滤介质劣化、
   管路结垢、电极污损等渐进性故障；22-30% MgSO₄ 溶液电导率远高于常规水体，为多频阻抗
   扫描提供了信噪比基础，普通淡水系统做同样扫描信号太弱。
2. 技术方案概要：循环液路多节点布置电极对，多频交流激励采集阻抗谱，用谱形变化反推
   过滤介质堵塞、管壁结垢、电极污损、气泡夹带等状态。
3. 去环境测试：拿掉 E1 → 信噪比骤降，不成立🟢；不涉及人体，法律风险最低。
4. 协同点：EIS本身成熟（血糖仪、燃料电池、润滑油领域），但"高盐漂浮液循环系统多点部署
   +谱形分类故障归因"是新场景组合，高电导率是使能条件。
5. 指标：阻抗谱特征稳定性、故障归因准确率、维护预警提前时长、误报率。
6. 检索词：中文——"漂浮舱 电化学阻抗 液路诊断"、"高盐溶液 阻抗谱 结垢监测"；
   英文——"electrochemical impedance spectroscopy brine circulation fault",
   "EIS scaling biofilm detection recirculating tank"
7. 信心度：中。最担心化工循环冷却水领域已有类似高盐介质阻抗监测前案。
8. 需要实验：模拟不同故障（人工结垢、过滤介质部分堵塞），验证阻抗谱能否稳定区分故障类型。
```

### 新角度 B：密度可调作为主动控制变量（把角度五做实）

```
1. 技术问题：现有浴缸/水疗设备水密度固定为1，用户体位体重差异只能被动接受浸没深度和
   压力分布；本舱密度连续可调，但目前只是初配时一次性设定，没有设备在使用中动态调整
   密度以达成特定浸没体积/压力目标。
2. 技术方案概要：以液位、静水压传感器测得的实际浸没体积/压力分布为反馈量，通过补水/
   补盐/局部脱盐动态调节密度，闭环逼近预设目标；控制对象是执行机构，不是人体生理状态。
3. 去环境测试：拿掉 E1 或 E2 → 均完全不成立🟢🟢，同时依赖两个必要条件。
4. 协同点：单独的"液位反馈控制"或"密度可调"都是已知手段，但组合成"以浸没体积/压力
   分布为目标的闭环"，功能上彼此支持，产生"连续可控浸没深度"的新效果。
5. 指标：目标/实际浸没体积偏差、调节响应时间、密度调节精度、压力分布均匀度。
6. 检索词：中文——"液体密度闭环控制 浸没体积"；英文——"closed-loop density control
   immersion volume", "buoyancy feedback brine concentration adjustment bath"
7. 信心度：中高。最担心撞上工业盐水配比自动控制（水处理软化剂、盐场卤水浓度控制）的
   通用专利。
8. 需要实验：验证补盐/稀释响应速度能否支撑舱内实时闭环，而非仅开舱前静态配液。
```

### 新角度 C：头空间气体微环境与液面下环境解耦控制

```
1. 技术问题：现有密闭舱体通常整舱统一控制温湿度、气体成分，但使用者口鼻始终位于液面
   上方的小体积头空间内，该空间同时受液面蒸发（受E1影响蒸汽组分特殊）和舱体新风共同
   支配，现有整舱式控制无法独立管理这个唯一呼吸空间。
2. 技术方案概要：头空间单独布置气体传感与微气流执行机构，依据局部读数单独控制该区域
   换气速率/气流方向，解耦头空间与舱体大环境的控制回路。
3. 去环境测试：拿掉E1→必要性下降但不消失🟡；拿掉E6（非密闭）→完全不成立🟢。
4. 协同点：可能与你现有"传感器沉默失效"发明点组合——头空间独立读数可作为主传感器
   失效时的交叉验证信号源，形成冗余安全效果。
5. 指标：头空间气体浓度稳定性、局部换气响应延迟、与主舱读数交叉验证一致性、结晶失效
   检出提前量。
6. 检索词：中文——"头部空间 局部通风 独立控制"；英文——"breathing zone microenvironment
   localized ventilation enclosed chamber"
7. 信心度：低到中。最担心潜水罩、太空舱、防护服领域已有呼吸区独立微环境控制的成熟布局。
8. 需要实验：测量头空间与整舱气体读数的实际差异幅度和时滞，判断是否有可测量的实质差异。
```

**优先级建议**：角度A、B优先检索验证；角度C信心最低，建议搁置，资源集中在A、B。

## 第三部分：多元素配方 / 体系创新 / 自有软件 评审

### 方向一：多重微量元素漂浮液

```
1. 技术问题：现有漂浮液多以单一MgSO₄提升密度；引入多种微量元素（锌、锰、硒、锂等）
   会带来不同元素溶解度、结晶温度、导电率贡献、与舱体材料腐蚀/沉淀反应各异的新工程
   矛盾——多盐同时溶解不冲突结晶、不加速腐蚀、密度仍可控。
2. 技术方案概要：以设备物理量描述配比逻辑——浓度区间、总体电导率范围、结晶温度余量、
   与已有过滤/加热/传感模块的相容性参数；若与设备形成闭环（实时监测浓度漂移自动补料）
   可做方法/系统权利要求。
3. 去环境测试：拿掉E1→多元素相互作用问题基本不存在，不成立🟢。
4. 协同点：US20150320087A1已公开多金属微量元素溶液（锌锰硒铜+维生素B12），配方本身
   路径大概率不新颖。机会窗口在"配方与舱体设备的相互作用"——某几种元素组合加速特定
   材质腐蚀或传感器结晶，设备针对性做了材料/传感器适配，这种"配方+设备联动"才可能
   有非显而易见性。
5. 指标：元素浓度稳定性（周期漂移量）、结晶温度裕量、材料腐蚀速率、传感器透气孔结晶
   时间对比基线。
6. 检索词：中文——"多元素矿物盐溶液 配方 浴用"、"微量元素 硫酸镁 复配 结晶抑制"；
   英文——"multi-mineral trace element bathing solution formula",
   "magnesium sulfate trace mineral combination crystallization inhibition"
7. 信心度：低（配方本身）；中（配方+设备联动）。死海盐浴、温泉理疗、农业微量元素液已
   有大量配方类专利/论文。
8. 需要实验：验证不同元素组合对结晶点、腐蚀速率、传感器透气孔堵塞时间的实测影响，找出
   能与"沉默失效"发明点组合的具体元素组合。
```

**红线提醒**：卖点若涉及"补充身体所需矿物质""经皮吸收改善健康"，直接踩疗效红线，且落入第25条边界。表达必须锁定工程问题（结晶、腐蚀、导电率、设备相容性），不涉及人体吸收效果。

### 方向二：设备+运营系统的"体系创新"——不建议整体打包申请

```
1. 技术问题：若"体系创新"指设备+会员管理+预约系统+数据看板的整合，本质是业务流程组合，
   不是技术问题的解决。专利法第25条第(二)项排除"智力活动的规则和方法"，纯商业模式不
   授权；只有运营系统中包含解决具体技术问题的技术特征（如用传感器数据自动触发设备维护
   调度），才可能被认定为技术方案。
2. 技术方案概要：不要以"体系"作为权利要求主语，拆解出体系里哪个环节存在具体技术问题，
   单独成案。如：传感器数据→维护调度算法→自动生成工单，这条子链条若证明用技术手段
   解决了技术问题（非纯排班规则），可能可专利；"会员预约""收费模式""连锁管理"等纯运营
   环节不是专利客体。
3. 去环境测试：不适用——风险不在依赖哪个环境条件，而在客体门槛本身，客体审查早于
   新创性审查。
4. 协同点：审查指南明确"算法+技术特征"可以是客体（提升硬件运算效率、数据处理可靠性），
   但"业务流程+软件实现"本身不满足，除非业务规则执行依赖并改进了底层技术手段。
5. 指标：不适用于整体"体系"，需拆到具体子系统后才能定义（故障预测准确率、维护响应
   时间、数据处理延迟）。
6. 检索词：中文——"设备物联网 运营管理系统 专利客体"；英文——"IoT equipment maintenance
   scheduling patent eligible subject matter"
7. 信心度：低（整体体系专利）。中国审查员对"伪装成技术方案的商业模式"审查严格。
8. 建议动作：不打包整体体系，从中挑1-2个有明确技术特征的子环节（最可能是"传感器数据
   驱动的设备自诊断/维护"）单独立案；商业整合部分留作商业秘密或版权保护。
```

### 方向三：内部自有软件——三个方向中最有操作空间

```
1. 技术问题：需先分类软件功能。纯数据展示看板、排班算法、客户管理逻辑属智力活动规则，
   第25条排除；若软件处理传感器原始数据的算法（如"盐雾暴露累计时长+读数呆滞度"致盲
   判据）提升了数据处理可靠性/精度，或改进计算机系统内部性能，按2024年生效审查指南，
   属于第2条第2款"技术方案"，是可专利客体。
2. 技术方案概要：拆分为"输入是否为技术领域数据（传感器物理量）→算法处理→输出是否为
   技术效果（设备控制指令、故障判据、精度提升）"链路写权利要求，避免"计算数值然后
   展示"这种纯计算+展示表达。
3. 去环境测试：类比问——"输入变成任意常规传感器数据，算法逻辑还成立吗？"若只是通用
   统计/机器学习模板换数据源，创造性弱；若专门针对本环境数据特征（高盐传感器漂移
   模式、中性浮力信号缺失模式）做了专门处理，更可能有创造性。
4. 协同点：2023版审查指南新增——算法若"提升硬件运算效率或执行效果""提升数据处理
   可靠性或精度""应用大数据技术提高处理结果可靠性"，即认定为技术方案。不要主张算法
   本身多聪明，要主张让系统在高盐高噪声环境下的判断可靠性/精度有可测量提升。
5. 指标：故障判断准确率、误报率、算法处理延迟、相对通用算法基线的精度提升幅度。
6. 检索词：中文——"传感器数据处理算法 专利客体 技术特征"；英文——"sensor data
   processing algorithm patent eligibility technical effect"
7. 信心度：中。2024年审查口径放宽是积极信号，但若软件本质是"调库调参数的业务逻辑"，
   包装再多技术词汇也难通过实质审查。
8. 建议动作：把现有自有软件模块逐个列出，标注每个模块输入（是否技术领域物理量数据）
   和输出（是否设备控制指令/技术判据），只有满足"技术数据进、技术效果出"模式的模块
   才值得投入专利资源，其余作软件著作权登记或商业秘密处理。
```

**三方向优先级**：体系创新——建议现在放弃整体打包思路，客体阶段大概率被驳回，不值得投代理费。多元素配方——值得做，但机会窗口只在"配方与设备相互作用"这个窄缝。自有软件——三者中最有操作空间，2023/2024审查指南修改明确给算法类专利开了口子[web:35][web:36]。

| 医疗级科研穿戴 | 学术研究中使用Zephyr BioPatch记录ECG/心率/呼吸率、QardioArm血压计（非商用漂浮舱标配，仅科研场景） | Floatation-REST心血管研究 [web:62] |

**观察**：硬件层面，行业已经把"消毒（UV+臭氧+AOP）""过滤（微米级+钛合金加热）""基础环境传感（温度/漏水/舱盖）"做到相当成熟的程度，且已有法规（如NACCHO/MAHC规范）明确要求臭氧≤0.1ppm、UV传感器校准、故障告警[web:63]。但你任务书里点出的"高盐蒸汽在传感器透气孔结晶导致沉默失效"这个具体故障模式，在这些产品资料里完全没有被提及——行业目前的自诊断还停留在"传感器电路层面"（断路、短路），没有触及"透气孔物理堵塞但电路正常"这一层，这印证了你现有发明点的稀缺性。

### 4.3 基于软硬件全景的补充新角度

结合上述调研，有两个此前未讨论、且现有产品资料中未见公开的角度：

```
【补充角度 D】跨模块信号交叉验证的一致性判据
1. 技术问题：现有产品的传感器（温度、漏水、舱盖、UV/臭氧浓度）彼此独立工作、独立
   告警，没有看到公开资料显示有产品把"多个本应相关的传感器读数之间的一致性"作为
   判据——例如加热器功率与温度传感器读数的期望关系、臭氧投加量与臭氧传感器读数的
   期望关系，一旦实际关系偏离预期但单个传感器电路自检仍显示正常，现有系统检测不出。
2. 技术方案概要：建立多模块间的物理量期望关系模型（如加热功率-温升速率、投药量-
   浓度读数），持续比对实际值与期望值的偏离度，偏离超出阈值即判定为"关系异常"，
   与单点阈值告警并行、互补。
3. 去环境测试：拿掉E1（高盐导致的特殊结晶/腐蚀故障模式）→ 该方案的必要性下降，但
   跨模块一致性校验本身在其他行业已是常规手段（如工业过程控制的软测量/软传感器），
   需要证明本环境的模块关系（如高盐环境下加热效率的特殊变化规律）足够独特才能过
   去环境测试🟡。
4. 协同点：与你现有的"沉默失效"发明点可以直接组合——沉默失效是"单点读数呆滞"，
   本方案是"多点关系异常"，两者互补覆盖不同故障模式，形成更完整的诊断体系。
5. 指标：跨模块关系偏离度、故障检出时间提前量（相对单点阈值告警）、误报率。
6. 检索词：中文——"多传感器一致性校验 工业软测量"、"设备状态跨模块关联诊断"；
   英文——"cross-sensor consistency validation soft sensor fault detection",
   "multi-parameter correlation anomaly detection equipment diagnosis"
7. 信心度：中。软测量/软传感器在工业过程控制领域是成熟概念，机会窗口在于"针对高盐
   漂浮舱特有的模块关系"这个具体应用场景，而非方法本身。
8. 需要实验：建立正常工况下各模块关系的基线曲线，验证高盐环境下这些关系是否与常规
   淡水系统显著不同，从而支撑"必须依赖E1"这一条。
```

```
【补充角度 E】高盐环境下 H2O2/臭氧检测试剂与传感器读数漂移补偿
1. 技术问题：行业内已有实践证明，通用H2O2检测工具在饱和硫酸镁溶液中可能读数不准，
   需要专用试剂盒验证（如Taylor K-1825/K-1826）才能准确测量，这说明高盐介质本身会
   干扰常规化学检测方法的准确性。但目前看到的做法是"更换验证过的试剂盒"，属于人工
   操作层面，没有看到产品把"电子传感器在高盐介质中的读数漂移自动补偿"做成设备内置
   功能。
2. 技术方案概要：针对UV/臭氧/H2O2电子传感器，建立高盐浓度（或电导率）与读数偏移量
   的补偿模型，实时根据当前液体电导率读数动态修正臭氧/H2O2浓度传感器输出，而非依赖
   人工更换试剂盒或定期校准。
3. 去环境测试：拿掉E1→补偿模型的必要性完全消失，淡水环境下无此问题🟢。
4. 协同点：与角度A（EIS液路电学指纹）存在天然协同——电导率数据本身可以复用为浓度
   传感器的补偿输入，一份多频阻抗测量数据同时服务两个目的，形成模块间的功能性支撑
   而非简单叠加。
5. 指标：补偿后读数与实验室基准值的偏差、补偿响应延迟、相对未补偿基线的精度提升。
6. 检索词：中文——"高盐介质 传感器读数补偿 电导率修正"；英文——"salinity compensation
   sensor drift ozone hydrogen peroxide measurement", "ionic strength interference
   correction electrochemical sensor"
7. 信心度：中高。水产养殖、海水淡化领域可能已有盐度补偿传感器的类似技术，需要专门
   检索这些邻域是否已覆盖臭氧/H2O2这两个具体检测对象在高盐介质中的补偿方法。
8. 需要实验：在不同盐浓度梯度下测量臭氧/H2O2传感器读数偏移曲线，验证偏移是否可用
   电导率单一变量建模，还是需要多变量补偿。
```

|---|---|---|---|
